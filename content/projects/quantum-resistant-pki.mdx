## Executive Overview

With advances in quantum computing, standard RSA-2048 and ECDSA elliptic curve primitives are vulnerable to Shor's algorithm and store-now-decrypt-later (SNDL) espionage campaigns. 

This project spearheaded the architectural transition of core internal PKI infrastructure to hybrid **Post-Quantum Cryptography (PQC)** standards—combining classical X25519 with **ML-KEM (Kyber-768)** for key encapsulation and **ML-DSA (Dilithium)** for certificate verification across x86 and ARM server clusters.

## Technical Highlights

### 1. Hybrid KEM (Key Encapsulation Mechanism)
To guard against implementation flaws in nascent lattice schemes while ensuring forward secrecy against quantum adversaries, we deployed hybrid key encapsulation combining **X25519** and **ML-KEM-768**:

```rust
// Rust Post-Quantum Handshake Negotiation snippet
use pqcrypto_traits::kem::*;
use pqcrypto_kyber::kyber768;

pub struct HybridHandshake {
    pub classical_share: [u8; 32],
    pub pqc_ciphertext: kyber768::Ciphertext,
}

impl HybridHandshake {
    pub fn encapsulate(public_key: &kyber768::PublicKey) -> (Self, [u8; 64]) {
        let (shared_secret_pq, ciphertext) = kyber768::encapsulate(public_key);
        let (classical_share, classical_secret) = generate_x25519_share();
        let combined_secret = kdf_combine(&shared_secret_pq, &classical_secret);
        (HybridHandshake { classical_share, pqc_ciphertext: ciphertext }, combined_secret)
    }
}
```

### 2. Payload Overhead & MTU Tuning
PQC public keys and ciphertexts are considerably larger than classical curves (1,184 bytes for ML-KEM vs 32 bytes for X25519). We engineered custom TCP window scaling and socket buffer tuning on our edge reverse proxies to prevent extra RTT round-trips during TLS handshakes.
